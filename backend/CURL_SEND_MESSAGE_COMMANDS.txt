# CURL COMMANDS FOR SENDING MESSAGES - CommAPP API

## Prerequisites
1. First, get an authentication token by logging in:
```bash
curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "your-email@example.com", "password": "your-password"}'
```

2. Extract the token from the response and use it in the message requests.

---

## 1. SEND MESSAGE IN GENERAL CHAT ROOM

### Basic Text Message:
```bash
curl -X POST http://localhost:5000/api/chat/rooms/CHAT_ROOM_ID/messages \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN_HERE" \
  -d '{
    "content": "Hello everyone! How is everyone doing today?",
    "messageType": "text"
  }'

## 4. MESSAGE MANAGEMENT

### Edit Your Own Message:
```bash
curl -X PUT http://localhost:5000/api/chat/messages/MESSAGE_ID_HERE \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN_HERE" \
  -d '{
    "content": "Updated message content here",
    "roomId": "CHAT_ROOM_ID_HERE"
  }'
```

### Delete Your Own Message:
```bash
curl -X DELETE http://localhost:5000/api/chat/messages/MESSAGE_ID_HERE \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN_HERE" \
  -d '{
    "roomId": "CHAT_ROOM_ID_HERE"
  }'
```

### Mark Message as Read:
```bash
curl -X POST http://localhost:5000/api/chat/messages/MESSAGE_ID_HERE/read \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_JWT_TOKEN_HERE" \
  -d '{

## 6. COMPLETE WORKFLOW EXAMPLE

### Step 1: Login and Get Token
```bash
LOGIN_RESPONSE=$(curl -s -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "password123"}')

TOKEN=$(echo $LOGIN_RESPONSE | grep -o '"token":"[^"]*' | cut -d'"' -f4)
echo "Token: $TOKEN"
```

### Step 2: Get Your Chat Rooms
```bash
curl -X GET http://localhost:5000/api/chat/rooms/user \
  -H "Authorization: Bearer $TOKEN"
```

### Step 3: Send a Message
```bash
curl -X POST http://localhost:5000/api/chat/rooms/ROOM_ID_HERE/messages \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "content": "Hello from the workflow example!",
    "messageType": "text"
  }'
```

### Step 4: Get Updated Messages
```bash
curl -X GET "http://localhost:5000/api/chat/rooms/ROOM_ID_HERE/messages?limit=10" \
  -H "Authorization: Bearer $TOKEN"
```

## 8. IMPORTANT NOTES

1. **Replace Placeholders:**
   - `YOUR_JWT_TOKEN_HERE` with actual token from login response
   - `CHAT_ROOM_ID_HERE` with actual chat room ID
   - `EVENT_ID_HERE` with actual event ID
   - `MESSAGE_ID_HERE` with actual message ID

2. **Authentication:** All message endpoints require valid JWT token

3. **Permissions:** 
   - Event chat: Only event attendees can send messages
   - General chat: Only room participants can send messages
   - Edit/Delete: Only the message sender can modify their messages

4. **Message Length:** Maximum 2000 characters for message content

5. **Response Format:** All successful responses return:
   ```json
   {
     "success": true,
     "data": { /* message data */ },
     "message": "Message sent successfully"
   }
   ```

6. **Error Handling:** Check response status codes:
   - 200/201: Success
   - 400: Bad request/validation error
   - 401: Unauthorized (invalid token)
   - 403: Forbidden (no permission)
   - 404: Not found (invalid IDs)

## 10. TROUBLESHOOTING

### Common Issues:

1. **401 Unauthorized:** Check if your JWT token is valid and not expired
2. **403 Forbidden:** Ensure you have permission to send messages in that chat room
3. **404 Not Found:** Verify the chat room ID or event ID exists
4. **400 Bad Request:** Check message content length (max 2000 chars) and required fields

### Debug Commands:
```bash
# Test if backend is running
curl -X GET http://localhost:5000/api/auth/test-login

# Test token validity
curl -X GET http://localhost:5000/api/auth/me \
  -H "Authorization: Bearer YOUR_TOKEN"
